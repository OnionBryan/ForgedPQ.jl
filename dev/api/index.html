ML-KEM (FIPS 203)

MLKEM512, MLKEM768 and MLKEM1024 have the same functions; MLKEM768 is shown.

ForgedPQ.MLKEM768.keygen — Function
keygen() -> (; public_key, secret_key)
keygen(seed) -> (; public_key, secret_key)

ML-KEM.KeyGen (FIPS 203 Alg. 19). Without seed, d and z come from the OS CSPRNG. With a 64-byte seed = d ‖ z, the key pair is deterministic (ML-KEM.KeyGen_internal, Alg. 16). Destructures as pk, sk = keygen().

source
ForgedPQ.MLKEM768.encaps — Function
encaps(public_key) -> (; ciphertext, shared_secret)
encaps(public_key, m) -> (; ciphertext, shared_secret)

ML-KEM.Encaps (FIPS 203 Alg. 20) after the encapsulation key check of §7.2; an invalid key throws ArgumentError. With a 32-byte m, encapsulation is deterministic (ML-KEM.Encaps_internal, Alg. 17). Destructures as ct, ss = encaps(pk).

source
ForgedPQ.MLKEM768.decaps — Function
decaps(secret_key, ciphertext) -> shared_secret

ML-KEM.Decaps (FIPS 203 Alg. 21) after the decapsulation key check of §7.3. A ciphertext of the right length that fails re-encryption gives the implicit-rejection secret, not an error.

source

Encapsulation key check (FIPS 203 §7.2): length and every coefficient below q.

source
ForgedPQ.MLKEM768.check_secret_key — Function

Decapsulation key check (FIPS 203 §7.3): length and the stored H(ek).

Secret sharing and memory

ForgedPQ.shamir_share — Function
shamir_share(secret, k, n, p = 2^521 - 1) -> Vector{Tuple{Int, BigInt}}

Split secret (an integer in [0, p)) into n shares (x, f(x)) at x = 1..n, any k of which recover it. f has degree k − 1, its coefficients drawn from the OS CSPRNG; p must be a prime greater than n. Fewer than k shares give no information about the secret.

source
ForgedPQ.shamir_reconstruct — Function
shamir_reconstruct(shares, k, p = 2^521 - 1) -> BigInt

Lagrange interpolation at x = 0 from the first k of shares. Duplicate x-coordinates (mod p) throw ArgumentError. Shares carry no integrity: a modified share gives a wrong secret, not an error.

source
ForgedPQ.shamir_share_bytes — Function
shamir_share_bytes(secret_bytes, k, n) -> Vector{Tuple{Int, BigInt}}

Split raw bytes into Shamir shares. Convenience wrapper that handles BigInt encoding/decoding for byte-oriented secret material (keys, hashes).

source
ForgedPQ.shamir_reconstruct_bytes — Function
shamir_reconstruct_bytes(shares, k, nbytes) -> Vector{UInt8}

Reconstruct raw bytes from Shamir shares. nbytes is the expected output length (e.g., 32 for a 256-bit key).

source
ForgedPQ.Wipe.wipe! — Function
wipe!(x...)

Zero each array of plain data in place, behind a compiler barrier so the stores are not removed as dead. Accepts Arrays, Memory, BitArrays, views, reshapes, transposes and reinterprets of them, and vectors of arrays; read-only storage (e.g. the code units of a String) and non-plain element types throw ArgumentError. Returns x for one argument, nothing for several.

Per-level modules

The standard-name modules wrap these, which expose the full interface, including the deterministic variants under their FIPS names and, for ML-DSA, the internal and external-μ interfaces. Levels other than the one shown have the same functions.

ForgedPQ.MLKEM — Module

ML-KEM (FIPS 203) — Multi-level implementation via @eval module generation. Generates MLKEM.Category1 (ML-KEM-512), MLKEM.Category3 (ML-KEM-768), MLKEM.Category5 (ML-KEM-1024).

Architecture follows NistyPQC.jl pattern:

  • Shared primitives (NTT, reduce, basemul, CBD, compress) included once
  • Per-level constants + KEM functions compiled 3x with different constants
source
ForgedPQ.MLDSA — Module

ML-DSA (FIPS 204) — Multi-level implementation via @eval module generation. Generates MLDSA.Category2 (ML-DSA-44), MLDSA.Category3 (ML-DSA-65), MLDSA.Category5 (ML-DSA-87).

source
ForgedPQ.SLHDSA — Module

SLH-DSA (FIPS 205): the stateless hash-based signature standard, in all twelve parameter sets (SHA2 and SHAKE, at security categories 1, 3 and 5, each small (s) or fast (f)). Its security rests only on the hash function. Generates SLHDSA.SHA2128s ... SLHDSA.SHAKE256f.

Function and step names follow the FIPS 205 algorithms they implement. ADRS is a 32-byte buffer mutated in place, as in the specification.

source
ForgedPQ.FNDSA — Module

Falcon / FN-DSA — NTRU-lattice hash-and-sign signatures (Falcon round-3 spec v1.2, the basis of FN-DSA, to be standardized as NIST FIPS 206). Generates FNDSA.Falcon512 and FNDSA.Falcon1024. The math-level implementation for every degree n = 2..1024 lives in FNDSA.Falcon.

source
ForgedPQ.X25519 — Module

X25519 (RFC 7748 §5): Diffie–Hellman on Curve25519, y² = x³ + 486662x² + x over GF(2²⁵⁵ − 19), by the Montgomery ladder on u-coordinates. Two field engines: radix-2⁵¹ limbs (x25519) and a BigInt transcription of RFC 7748 §5 (x25519_ref), cross-checked in the tests.

source
ForgedPQ.XWing — Module

X-Wing: the X25519 + ML-KEM-768 hybrid KEM of draft-connolly-cfrg-xwing-kem-11 (§5), an individual Internet-Draft in the Independent Submission stream since -07 (2025-05-26); -11 refreshed the expired -10 with no normative change. IND-CCA if either X25519 (gap-CDH) or ML-KEM-768 is secure, with SHA3 as a random oracle (§6; proof in ePrint 2024/039). Against a quantum adversary, security rests on ML-KEM-768 (with SHA3-256 as a PRF), not on X25519. Keys and ciphertexts are the draft's fixed-length byte strings.

source
