Falcon-1024

ForgedPQ.FNDSA.Falcon1024.falcon_certify — Method

Exact certificate for sk: every ffLDL leaf σ/√d in [σmin, σmax] and Gram–Schmidt norm ≤ 1.17√q, decided without floating point (FalconCertify). Returns a NamedTuple with ok and the exact values.

source
ForgedPQ.FNDSA.Falcon1024.falcon_expand_sk — Method

Decode sk once and precompute its ffLDL tree, for repeated signing.

source
ForgedPQ.FNDSA.Falcon1024.falcon_keygen — Method

Generate a keypair; returns (pk, sk) in the spec byte encodings. With certified=true, only keys that pass the exact certificate (falcon_certify) are returned; fips206=true also tightens the GS bound to 0.9999·1.17√q (NIST FIPS 206 status update). fixedpoint=true generates the key with no floating point (ePrint 2023/290).

source

Internal modules

ForgedPQ — Module
ForgedPQ.jl — Post-Quantum Cryptography for Julia

Implementations of NIST FIPS post-quantum cryptographic standards:

  • ML-KEM (FIPS 203): Module-Lattice Key Encapsulation (Kyber) — 512/768/1024
  • ML-DSA (FIPS 204): Module-Lattice Digital Signatures (Dilithium) — 44/65/87
  • FN-DSA (Falcon): NTRU-lattice signatures — Falcon-512 / Falcon-1024; exact key certificate, float-free keygen, message recovery (FALCON-MRM)
  • X25519 (RFC 7748) and X-Wing (X25519 + ML-KEM-768 hybrid KEM)
  • Shamir: (k,n)-threshold secret sharing over GF(2^521-1)

ML-KEM and ML-DSA pass 855 NIST ACVP vectors across every interface; Falcon signing is byte-exact with the round-3 C reference implementation.

Quick Start

using ForgedPQ

# ML-KEM-768 key encapsulation
pk, sk = MLKEM768.keygen()
ct, ss = MLKEM768.encaps(pk)
@assert MLKEM768.decaps(sk, ct) == ss

# ML-DSA-65 signatures
pk, sk = MLDSA65.keygen()
msg = Vector{UInt8}("hello")
sig = MLDSA65.sign(sk, msg)
MLDSA65.verify(pk, msg, sig)  # true

# Falcon-512 signatures
pk, sk = Falcon512.keygen()
sig = Falcon512.sign(sk, msg)
Falcon512.verify(pk, msg, sig)  # true

The per-level modules (MLKEM.Category3.kyber_kem_keypair, ...) remain available.

ForgedPQ.Keccak — Module

Keccak-f[1600] and the FIPS 202 functions the package uses: SHAKE128, SHAKE256 and SHA3-224/256/ 384/512. The 25-lane state is an immutable tuple, so it stays in registers and on the stack and leaves no heap copy; the round function is straight-line code with constant rotation counts. Byte-identical to SHA.jl (test/keccak.jl).

source
ForgedPQ.Sha2 — Module

SHA-256 and SHA-512 (FIPS 180-4) from a caller-held state. SLH-DSA hashes millions of inputs that share their first block, PK.seed ‖ zero padding: that block is compressed once into a midstate and each hash is finished from it, with caller-owned scratch and no allocation. Byte-identical to SHA.jl (test/slhdsa.jl).

source
ForgedPQ.Prehash — Module

Pre-hash functions and their DER-encoded OIDs, shared by HashML-DSA (FIPS 204 §5.4) and HashSLH-DSA (FIPS 205 §10.2).

source
ForgedPQ.Wipe — Module

Zeroing of secret buffers the package owns; see SECURITY.md, "Secrets in memory".

source
ForgedPQ.Bytes — Module

Byte-string concatenation for hash inputs and encodings. Base.vcat on byte vectors carries an assertion whose message path is a runtime dispatch on Julia 1.12, which the dispatch gate (test/timing/dispatch.jl) reports on every secret path; catbytes preallocates and copies.
